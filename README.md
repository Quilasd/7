# 🎭 Мафия Онлайн — Telegram-бот

Полноценная онлайн-игра «Мафия» в Telegram: комнаты на 4–20 игроков, тайные
роли, ночные фазы, обсуждения, голосования, рейтинг, уровни, админ-панель.

- **Python 3.12+** (запускается и на 3.11)
- **aiogram 3.x** (async)
- **SQLAlchemy 2.x async** — SQLite для разработки, PostgreSQL для продакшена одной строкой в `.env`
- **Pydantic / pydantic-settings** — конфигурация и настройки комнат
- **pytest** — тесты игровой логики (52 теста)

## Требования

- Python **3.12+** (проверено на 3.11 и 3.12)

## Установка

```bash
git clone <repo-url> && cd <repo>
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt    # для разработки: pip install -r requirements-dev.txt
cp .env.example .env               # затем отредактируйте .env
```

## Настройка .env

Минимум — три значения:

```env
BOT_TOKEN=123456789:AaBb...        # токен от @BotFather
ADMIN_IDS=123456789                # ваш Telegram ID через запятую
OWNER_IDS=123456789                # глобальный Owner (уровень 5, полный доступ)
DATABASE_URL=sqlite+aiosqlite:///./data/mafia.db
```

Для PostgreSQL (нужен `pip install asyncpg`):

```env
DATABASE_URL=postgresql+asyncpg://mafia:mafia@localhost:5432/mafia
```

Полный список переменных — в [`.env.example`](.env.example).

## Игровая логика

### Фазы

```
WAITING (комната) → STARTING (отсчёт) → NIGHT → DAY → VOTING ─┐
                                    ▲__________________________┘
                                    └→ ENDED (проверка победы после каждой смены состояния)
```

Каждое действие валидируется по текущей фазе из БД: голосовать ночью нельзя,
использовать ночную способность днём нельзя, мёртвые не действуют и не голосуют.

### Порядок обработки ночи (расширяемый конвейер)

`NIGHT_PIPELINE` в `bot/roles/base.py`:

1. **BLOCK** — любовница блокирует игрока: все его ночные действия отменяются;
2. **PROTECT** — доктор лечит, телохранитель защищает (цель спасена);
3. **KILL** — мафия (консенсус большинства, при равенстве — случайный лидер) и
   маньяк (самостоятельно). Спасённая цель не умирает; телохранитель при этом
   погибает вместо неё. Несколько атак по одной цели = одна смерть;
4. **CHECK** — комиссар получает результат утром в личку.

Новая стадия = вставка в `NIGHT_PIPELINE` + обработчик в `night_resolver.py`.

### Победа

Проверяется после каждой смерти/смены фазы (`role_manager.evaluate_win`):

- 🔴 **Мафия**: мафии ≥ всех остальных живых;
- 🔵 **Мирные**: вся мафия уничтожена (и маньяк мёртв);
- 🔪 **Маньяк**: остался один или один из двух последних;
- 🤝 **Ничья**: все мертвы (или принудительное завершение админом).

### Голосование

- голосуют только живые, за себя голосовать нельзя;
- переголосование разрешено до конца этапа (обновляется существующая запись);
- правило ничьей настраивается в комнате: `revote` (повторный круг среди
  лидеров; вторая ничья — никто не умирает) или `no_death`.

### Рейтинг, XP и уровни

Стартовые значения нового игрока: **рейтинг 0, победы 0, XP 0, уровень 1**
(стартового рейтинга 1000 нет).

Формулы живут **только** в `bot/services/rating.py` (`RatingRules`) — хендлеры
их не знают. Значения по умолчанию:

| Событие | Рейтинг | XP |
|---|---|---|
| Участие | — | +10 |
| Победа | +100 | +25 |
| Поражение | +25 | — |
| Убийство (мафия/маньяк) | +5 | +5 |
| Спасение (доктор) | +5 | +5 |
| Расследование (комиссар) | +3 | +3 |
| Правильное голосование (за мафию, будучи мирным) | +2 | +2 |
| Выживание до конца игры | +10 | +5 |
| Ничья / принудительная остановка | 0 (антифарм) | 0 (антифарм) |

Уровни (`ProgressionService`): порог уровня L = `step + (L−2)·growth`, при
`step=100, growth=50` это 0 / 100 / 250 / 450 / 700 XP (дальше прогрессия
продолжается: 1000, 1325…). Формула меняется двумя константами.

Антифарм: XP и рейтинг начисляются только в `_end_game` нормально
завершённой игры; создание/отмена игр ничего не дают, ничья не начисляет.

## Группы и локальная статистика

Два **физически разделённых** уровня статистики:

- 🌐 **глобальный** — колонки `users` (rating/xp/level/wins/losses/
  games_played/kills/saves/investigations/correct_votes); виден везде;
- 🏠 **локальный** — строка `group_players` **конкретной группы** с тем же
  набором полей; существует только относительно группы.

Применением управляет `RatingService` (`apply_global` / `apply_local`) по
флагам из настроек группы (`GroupSettings`): `rating_enabled`,
`global_rating_enabled`, `local_rating_enabled`, `xp_enabled`,
`global_xp_enabled`, `local_xp_enabled` — глобальный и локальный скоупы
включаются/выключаются независимо. Игра в группе A меняет глобальные
показатели и показатели группы A, но никогда — группы B.

Профиль: в группе показывает блоки 🌐 ГЛОБАЛЬНО + 🏠 ЭТА ГРУППА; в личке —
глобальный. Топы: `/top` в группе по умолчанию локальный (с кнопкой 🌐), в
личке — глобальный; сортировки rating DESC / wins DESC / (level, xp) DESC.

Каждая Telegram-группа (`groups`: telegram_chat_id, title, created_at) имеет
свои `GroupSettings` (мин/макс игроков, таймеры ночи/дня/голосования,
tie_rule, роли, mafia_count, allow_maniac, все флаги рейтинга/XP,
debug_enabled) — игры в группе создаются по её правилам. `/settings` —
inline-меню по разделам, изменения сохраняются в БД (право MANAGE_SETTINGS).

## Многоуровневая администрация

Уровни (`bot/services/permissions.py`):

| Уровень | Название | Права (суммарно) |
|---|---|---|
| 0 | 👤 Player | — |
| 1 | 🛟 Helper | просмотр профилей/игроков/статистики, warn |
| 2 | 🔨 Moderator | + mute / kick / ban |
| 3 | ⚙️ Admin | + управление комнатами, старт/стоп игры, USE_DEBUG |
| 4 | 🎖 Senior Admin | + настройки, роли, broadcast, управление штатом и группой |
| 5 | 👑 Owner | все права, включая MANAGE_GLOBAL_SETTINGS |

Источники прав: `OWNER_IDS` → уровень 5 **везде** (глобальный Owner);
`ADMIN_IDS` → уровень 4 везде; `group_admins.admin_level` → уровень **только
в своей группе**. Эффективный уровень = max(глобальный, локальный); админ
группы A не имеет прав в группе B и в личке. Админ-панель `/admin` доступна
и владельцу, и администраторам (.env).

Защита штаба (`/staff_add` и др.): нельзя изменить собственный уровень,
выдать уровень ≥ своего, изменить администратора с уровнем ≥ своего, снять
Owner (уровень 5 назначается только через `OWNER_IDS`). Каждое действие
пишется в `audit_logs` (actor, target, group, action, details).

Поиск игрока в админ-командах (`UserLookupService`): Telegram ID (основной
идентификатор), `@username`, username без `@`, ответ реплаем на сообщение.

## Админ-команды

Основной модуль — `bot/handlers/groups_admin.py` (работает в группах и личке;
права проверяются относительно текущего чата через `PermissionService`).
Краткая карта (все команды защищены правами, действия — в AuditLog):

- **Профили:** `/player /player_stats /stats /players` (чужие профили — VIEW_PROFILE)
- **Модерация:** `/warn /unwarn /warnings /mute /unmute /kick /ban /unban`
- **Игра:** `/game /games /game_info /game_players /game_phase /game_start /game_stop /game_cancel /game_kill /game_revive`
- **Комнаты:** `/rooms /room /room_close /room_kick /room_force_start /createroom`
- **Штат:** `/staff /staff_add /staff_remove /staff_promote /staff_demote /staff_info`
- **Настройки:** `/settings` (inline-меню) + `/set_min_players /set_max_players /set_night_time /set_day_time /set_vote_time /set_roles`
- **Массовые:** `/broadcast /announce`
- **Система:** `/botstats /logs /reload /maintenance`
- **Только Owner (OWNER_IDS):** `/debug_help` — справочник всех команд с требуемыми правами + диагностика (распознан ли твой ID в OWNER_IDS/ADMIN_IDS, текущий уровень)

Топы и рейтинги — `bot/handlers/ratings.py` (`/top`, `/top_rating`,
`/top_wins`, `/top_levels`, пагинация, переключатель 🌐/🏠).

Добавление новой команды: один хендлер в соответствующем роутере + проверка
`await services.permissions.has(session, tg_id, group_id, Permission.X)` —
никаких изменений в ядре не нужно.

## Принятые решения (не указанные в ТЗ)

- **Маньяк для комиссии — «не мафия»** (классика; комиссар ищет именно мафию).
- **Мафия не может убивать своих** (кнопки союзников не показываются).
- **Доктор не лечит одну цель две ночи подряд** (правило классической мафии).
- **Телохранитель погибает, спасая цель** (жертвенная защита; сам себя защитить не может).
- **Заблокированный игрок не узнаёт о блокировке** — нет утечки информации.
- **Выход во время игры = смерть** игрока (`death_cause=left`) + проверка победы.
- **Создатель не может «выйти» из комнаты** — только закрыть её целиком.
- **Игрок состоит максимум в одной открытой комнате и одной активной игре.**
- **Роли при смерти** раскрываются/скрываются настройкой комнаты (`reveal_roles_on_death`).
- **Время хранится в UTC** (наивный datetime) — нет проблем с таймзонами.
- **Секреты не логируются**: в логах только ID игр/игроков и счётчики.
- **Глобальный и локальный рейтинг/XP/уровни физически разделены** (User vs
  GroupPlayer) — случайная перезапись невозможна по построению; формулы одни
  (`RatingRules`), хранилища разные.
- **Уровень Owner (5) назначается только через `OWNER_IDS` в .env** — через
  бот-команды уровень 5 выдать/снять нельзя (защита от захвата).
- **Глобальные ADMIN_IDS = Senior Admin (4) во всех чатах**, локальные
  GroupAdmin-уровни действуют только в своей группе.
- **Мут — через Telegram restrict_chat_member** (1–1440 минут); если бот не
  имеет прав администратора в группе — сообщаем об этом, а не падаем.
- **Изменение настроек группы через `/settings` пишется в AuditLog**
  (`group_setting`), как и остальные админ-действия.
- **DEBUG по умолчанию не трогает статистику** (`DEBUG_AFFECTS_*_STATS=false`)
  — включение флагов допускает намеренное изменение реальных данных при
  тестировании; боты тест-игр в топы/рассылки не попадают (is_test-фильтр).
- **В тестах используется файловая SQLite на каждый тест** (не StaticPool
  `:memory:`): единое общее соединение приводило к взаимному откату
  транзакций параллельных сессий (супервизор тест-игры vs игровой цикл).

## Миграции БД

Используется Alembic (async-env). Схема в едином источнике правды — моделях
`bot/database/models.py`; начальная миграция `0001` создаёт все таблицы.

```bash
# применить миграции
python -m alembic upgrade head

# создать новую ревизию после изменения моделей
python -m alembic revision -m "add table X" --autogenerate
```

URL БД берётся из `DATABASE_URL` (.env), `alembic.ini` — только фолбэк.

```python
    team=Team.CITY,
    description="Один раз за игру ночью нейтрализует игрока...",
    night_action=ActionType.KILL,      # или новый тип действия
    action_prompt="Кого нейтрализовать?",
    action_verb="Нейтрализовать",
    can_target_self=False,
    win_condition_text="Мирные побеждают, когда вся мафия уничтожена.",
))
```

2. Добавьте импорт в `bot/roles/__init__.py` — роль появится в настройках
   комнат, в ночных кнопках и в админ-панели автоматически.

3. Если роль вводит **новый тип ночного действия** — добавьте значение в
   `ActionType`, вставьте стадию в `NIGHT_PIPELINE` и обработчик в
   `night_resolver.resolve_night`. Существующие стадии менять не нужно.

4. При особом условии победы — расширьте `role_manager.evaluate_win`.

## Админ-панель

Команда `/admin` (доступ только для `ADMIN_IDS` из `.env`, права проверяются
на каждом действии):

- 📊 статистика бота (пользователи, игры, комнаты);
- 🎮 активные игры + принудительное завершение (рейтинг не меняется);
- 🏠 комнаты + закрытие;
- 🚫 бан / ✅ разбан по Telegram ID (забаненные не получают апдейтов);
- 📣 рассылка всем пользователям (с учётом `can_receive_dm`);
- 📜 последние строки лог-файла;
- 🎭 включение/отключение ролей глобально;
- ⚙️ глобальные тайминги фаз по умолчанию.

## Тестовый режим (DEBUG MODE)

Режим отладки полного игрового цикла без реальных игроков. Боты проходят
**настоящий движок** — отдельной игровой механики для debug нет
(GameManager / RoleManager / PhaseManager / NightResolver / VoteManager /
RatingService / ProgressionService / PermissionService / GroupSettings).

**Доступ (реальные проверки прав, обхода PermissionService нет):**

- глобальный Owner (`OWNER_IDS`) — всегда, в любой группе, даже с
  `debug_enabled=false`;
- уровни с правом `USE_DEBUG` (Admin+): в группе — только при включённом
  `group_settings.debug_enabled`, в личке — при `DEBUG_MODE=true`;
- Moderator и ниже доступ запрещены.

**Команды:** `/testgame`, `/testgame 6`, `/testgame fast` (таймеры 5 сек),
`/testgame 6 fast`, `/debug`, `/debug_game`, `/debug_state`, `/debug_phase`,
`/debug_finish_phase`.

Создаётся игра: **👤 вы + 🤖 TestPlayer1..N**. Что происходит:

- роли распределяются автоматически, ваша роль приходит в личку;
- боты **сами выполняют ночные действия** по правилам своих ролей
  (мафия стреляет, доктор лечит, комиссар проверяет и т.д.) и **сами голосуют**;
- тайминги ускоренные (обычная тест-игра 6 сек/фаза, `fast` — 5 сек),
  старт через 2 секунды;
- за вами остаётся право играть свою роль вручную (или включить авто и за себя);
- состояние игры (роли, действия, голоса) печатается **в консоль** и по кнопке.

Пульт управления тест-игрой (inline-кнопки под сообщением):

| Кнопка | Действие |
|---|---|
| 📋 Состояние | дамп игры в чат + в консоль (роли видны — это отладка) |
| ⏩ Пропустить фазу | мгновенно завершает текущую фазу (ускорение таймеров) |
| 🤖 Действия ботов | выполнить авто-действия прямо сейчас |
| 🟢/🔴 Авто ботов | вкл/выкл автоматические действия ботов |
| 🏁 Завершить игру | принудительный финал |

**Статистика тестовых игр** управляется флагами (по умолчанию выключены):

```env
DEBUG_AFFECTS_GLOBAL_STATS=false   # true — тест-игры меняют ГЛОБАЛЬНУЮ статистику
DEBUG_AFFECTS_LOCAL_STATS=false    # true — тест-игры меняют ЛОКАЛЬНУЮ статистику группы
```

Все 4 комбинации тестируются отдельно (только глобальный / только локальный /
оба / ничего). При выключенных флагах финал игры прямо сообщает:
«🧪 Тестовая игра — статистика и рейтинг не изменены».

**Изоляция от обычных игр:**

- у тестовых игр стоит флаг `games.settings["test_mode"]` — все методы режима
  работают только с такими играми (обычную игру «пропустить» или завершить через
  `/testgame` нельзя);
- боты — пользователи с `users.is_test=True` и **отрицательными** `telegram_id`
  (реальные Telegram ID пользователей не бывают отрицательными);
- боты исключены из рейтинга, общей статистики и рассылок;
- комнаты тестовых игр приватные — их не видно в общем списке;
- ботам ничего не отправляется в Telegram (нотификатор игнорирует отрицательные ID).

Сервисный слой — `bot/services/test_game.py` (`TestGameManager`), хендлер —
`bot/handlers/testgame.py`. Поведение ботов детерминировано
(RNG с seed от `game_id` и номера дня) — тесты воспроизводимы.

## Тесты

```bash
python -m pytest tests/ -v
```

Покрыто критичное:

- **движок:** распределение ролей, условия победы (мафия/мирные/маньяк/ничья),
  ночной конвейер (убийство, лечение, жертва телохранителя, блокировка,
  проверка), голосование (большинство, ничья, переголосование, валидации),
  полный игровой цикл до победы с обновлением статистики, восстановление
  после рестарта, smoke-тест сборки приложения;
- **прогрессия:** старт с нуля, пороги 0/100/250/450/700, сменяемость
  формулы, формулы RatingService (победа/поражение/вклад/антифарм-ничья,
  независимые флаги rating/xp);
- **группы и локальная статистика:** создание, разные настройки, изоляция
  A↔B и User↔GroupPlayer, локальные топы, warn/локальный бан;
- **permissions:** права всех уровней, глобальный Owner везде, A-админ ≠
  B-админ, все правила защиты штаба, аудит;
- **lookup:** Telegram ID, @username, username без @, reply, приоритет
  запроса над reply, неизвестный пользователь;
- **скоупы рейтинга (сквозные, через реальный движок):** игра в группе
  меняет глобальный + локальный A и не трогает B; все комбинации
  выключения global/local rating и XP;
- **DEBUG MODE:** создание тест-игр, fast-режим (5 сек), авто-действия
  ботов, супервизор, изоляция от обычных игр, все 4 комбинации
  `DEBUG_AFFECTS_*_STATS`, доступ по уровням (Owner переопределяет
  `debug_enabled=false` группы, Moderator отказ).

## Логирование

Консоль + ротатируемый файл (`LOG_FILE`, 2 МБ × 3). Уровень — `LOG_LEVEL`
(INFO/WARNING/ERROR/DEBUG). Логируются: создание/старт/завершение игр, действия
(только ID), ошибки. Секретные роли и приватные действия в логи не пишутся.
