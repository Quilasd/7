# 🎭 Мафия Онлайн — Telegram-бот

Полноценная онлайн-игра «Мафия» в Telegram: комнаты на 4–20 игроков, тайные
роли, ночные фазы, обсуждения, голосования, рейтинг, уровни, админ-панель.

- **Python 3.12+** (запускается и на 3.11)
- **aiogram 3.x** (async)
- **SQLAlchemy 2.x async** — SQLite для разработки, PostgreSQL для продакшена одной строкой в `.env`
- **Pydantic / pydantic-settings** — конфигурация и настройки комнат
- **pytest** — тесты игровой логики (52 теста)

## Возможности

| Раздел | Что реализовано |
|---|---|
| Главное меню | inline-меню: Играть / Создать комнату / Найти игру / Профиль / Рейтинг / Правила / Настройки |
| Профиль | имя, ID, игры, победы/поражения, % побед, убийства, спасения, правильные голосования, рейтинг, уровень/XP |
| Комнаты | публичные/приватные (пароль хэшируется PBKDF2), 4–20 игроков, готовность, кик, настройки, закрытие |
| Роли | 🔴 мафия, 🔵 мирный, 🕵️ комиссар, ❤️ доктор, 🔪 маньяк, 👰 любовница, 🛡 телохранитель |
| Игра | состояния WAITING→STARTING→NIGHT→DAY→VOTING→ENDED, распределение ролей, ночные действия, утро, день, голосование, победные условия |
| Защита | двойные нажатия, действия после смерти/фазы, выход во время игры, рестарт бота, устаревшие кнопки, баны |
| Таймеры | asyncio-задачи, не блокируют event loop; состояние игр восстанавливается из БД после рестарта |
| Рейтинг | Elo-подобное изменение, XP, уровни, топ-10 |
| Админка | статистика, активные игры/комнаты, бан/разбан, принудительный финал, рассылка, логи, управление ролями, глобальные параметры |

## Требования

- Python **3.12+** (проверено на 3.11 и 3.12)
- Токен бота от [@BotFather](https://t.me/BotFather)
- (опционально) Docker / Docker Compose

## Установка

```bash
git clone <repo-url> && cd <repo>
python3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt    # для разработки: pip install -r requirements-dev.txt
cp .env.example .env               # затем отредактируйте .env
```

## Настройка .env

Минимум — два значения:

```env
BOT_TOKEN=123456789:AaBb...        # токен от @BotFather
ADMIN_IDS=123456789                # ваш Telegram ID через запятую
DATABASE_URL=sqlite+aiosqlite:///./data/mafia.db
```

Для PostgreSQL (нужен `pip install asyncpg`):

```env
DATABASE_URL=postgresql+asyncpg://mafia:mafia@localhost:5432/mafia
```

Полный список переменных — в [`.env.example`](.env.example).

## Запуск

```bash
python -m bot.main
```

При первом старте таблицы создаются автоматически (`AUTO_CREATE_TABLES=true`).
Для продакшена отключите автосоздание и используйте [alembic](#миграции-бд).

Запуск тестов:

```bash
python -m pytest tests/ -v
```

## Игровая логика

### Фазы

```
WAITING (комната) → STARTING (отсчёт) → NIGHT → DAY → VOTING ─┐
                                    ▲__________________________┘
                                    └→ ENDED (проверка победы после каждой смены состояния)
```

Каждое действие валидируется по текущей фазе из БД: голосовать ночью нельзя,
использовать ночную способность днём нельзя, мёртвые не действуют и не голосуют.

### Порядок обработки ночи (расширяемый конвейер)

`NIGHT_PIPELINE` в `bot/roles/base.py`:

1. **BLOCK** — любовница блокирует игрока: все его ночные действия отменяются;
2. **PROTECT** — доктор лечит, телохранитель защищает (цель спасена);
3. **KILL** — мафия (консенсус большинства, при равенстве — случайный лидер) и
   маньяк (самостоятельно). Спасённая цель не умирает; телохранитель при этом
   погибает вместо неё. Несколько атак по одной цели = одна смерть;
4. **CHECK** — комиссар получает результат утром в личку.

Новая стадия = вставка в `NIGHT_PIPELINE` + обработчик в `night_resolver.py`.

### Победа

Проверяется после каждой смерти/смены фазы (`role_manager.evaluate_win`):

- 🔴 **Мафия**: мафии ≥ всех остальных живых;
- 🔵 **Мирные**: вся мафия уничтожена (и маньяк мёртв);
- 🔪 **Маньяк**: остался один или один из двух последних;
- 🤝 **Ничья**: все мертвы (или принудительное завершение админом).

### Голосование

- голосуют только живые, за себя голосовать нельзя;
- переголосование разрешено до конца этапа (обновляется существующая запись);
- правило ничьей настраивается в комнате: `revote` (повторный круг среди
  лидеров; вторая ничья — никто не умирает) или `no_death`.

### Рейтинг, XP, уровни

| Событие | Рейтинг | XP |
|---|---|---|
| Победа (город/мафия) | +25 | 10 (участие) + 25 (победа) |
| Победа маньяка | +40 | аналогично |
| Поражение | −12 (не ниже 0) | 10 |
| Убийство | — | +5 |
| Успешное спасение | — | +5 |
| Правильное голосование (за мафию, будучи мирным) | — | +2 |

Уровень: квадратичная шкала — 100 XP до 2-го уровня, далее +50 за каждый
уровень (150, 200, 250…). Стартовый рейтинг — 1000.

## Принятые решения (не указанные в ТЗ)

- **Маньяк для комиссии — «не мафия»** (классика; комиссар ищет именно мафию).
- **Мафия не может убивать своих** (кнопки союзников не показываются).
- **Доктор не лечит одну цель две ночи подряд** (правило классической мафии).
- **Телохранитель погибает, спасая цель** (жертвенная защита; сам себя защитить не может).
- **Заблокированный игрок не узнаёт о блокировке** — нет утечки информации.
- **Выход во время игры = смерть** игрока (`death_cause=left`) + проверка победы.
- **Создатель не может «выйти» из комнаты** — только закрыть её целиком.
- **Игрок состоит максимум в одной открытой комнате и одной активной игре.**
- **Роли при смерти** раскрываются/скрываются настройкой комнаты (`reveal_roles_on_death`).
- **Время хранится в UTC** (наивный datetime) — нет проблем с таймзонами.
- **Секреты не логируются**: в логах только ID игр/игроков и счётчики.

## Миграции БД

Используется Alembic (async-env). Схема в едином источнике правды — моделях
`bot/database/models.py`; начальная миграция `0001` создаёт все таблицы.

```bash
# применить миграции
python -m alembic upgrade head

# создать новую ревизию после изменения моделей
python -m alembic revision -m "add table X" --autogenerate
```

URL БД берётся из `DATABASE_URL` (.env), `alembic.ini` — только фолбэк.

## Добавление новой роли

1. Создайте `bot/roles/<role>.py` и зарегистрируйте роль:

```python
# bot/roles/sniper.py
from bot.roles.base import ActionType, Role, Team, register_role

register_role(Role(
    id="sniper",
    name="СНАЙПЕР",
    emoji="🎯",
    team=Team.CITY,
    description="Один раз за игру ночью нейтрализует игрока...",
    night_action=ActionType.KILL,      # или новый тип действия
    action_prompt="Кого нейтрализовать?",
    action_verb="Нейтрализовать",
    can_target_self=False,
    win_condition_text="Мирные побеждают, когда вся мафия уничтожена.",
))
```

2. Добавьте импорт в `bot/roles/__init__.py` — роль появится в настройках
   комнат, в ночных кнопках и в админ-панели автоматически.

3. Если роль вводит **новый тип ночного действия** — добавьте значение в
   `ActionType`, вставьте стадию в `NIGHT_PIPELINE` и обработчик в
   `night_resolver.resolve_night`. Существующие стадии менять не нужно.

4. При особом условии победы — расширьте `role_manager.evaluate_win`.

## Docker

Одна команда (нужен заполненный `.env` рядом с `docker-compose.yml`):

```bash
docker compose up --build -d
docker compose logs -f bot
```

БД SQLite хранится в volume `mafia_data` и переживает пересоздание контейнера.
Для PostgreSQL раскомментируйте сервис `db` в `docker-compose.yml`, добавьте
`asyncpg` в requirements и смените `DATABASE_URL`.

## Админ-панель

Команда `/admin` (доступ только для `ADMIN_IDS` из `.env`, права проверяются
на каждом действии):

- 📊 статистика бота (пользователи, игры, комнаты);
- 🎮 активные игры + принудительное завершение (рейтинг не меняется);
- 🏠 комнаты + закрытие;
- 🚫 бан / ✅ разбан по Telegram ID (забаненные не получают апдейтов);
- 📣 рассылка всем пользователям (с учётом `can_receive_dm`);
- 📜 последние строки лог-файла;
- 🎭 включение/отключение ролей глобально;
- ⚙️ глобальные тайминги фаз по умолчанию.

## Тесты

```bash
python -m pytest tests/ -v
```

Покрыто критичное: распределение ролей, условия победы (мафия/мирные/маньяк/ничья),
ночной конвейер (убийство, лечение, жертва телохранителя, блокировка, проверка),
голосование (большинство, ничья, переголосование, валидации), полный игровой
цикл до победы с обновлением статистики, восстановление после рестарта,
smoke-тест сборки приложения.

## Логирование

Консоль + ротатируемый файл (`LOG_FILE`, 2 МБ × 3). Уровень — `LOG_LEVEL`
(INFO/WARNING/ERROR/DEBUG). Логируются: создание/старт/завершение игр, действия
(только ID), ошибки. Секретные роли и приватные действия в логи не пишутся.
